# v0.1.2 Release Plan

**Goal:** release the existing integrated fixes only after local and Pi verification, preserving private runtime configuration.

**Approach:** use the established pygame/Flask runtime, existing tests and existing Pi service. Sync project files without reinstalling the service or editing system/network files. Retain project-local rollback backups and publish only redacted evidence.

**Scope:** approved release procedure in this conversation; candidate baseline `b56e3c0`, [candidate record](../../v0.1.2-rc.1.md).

## Gates

- [x] Verify clean source baseline and Pi connection/service.
- [x] Add focused regression tests and shared REST/WebSocket input validation for configuration-corrupting inputs. Keep valid existing forms and compatibility routes working.
- [x] Run compile, smoke, unittest, shell/JS syntax and security checks locally.
- [x] Back up the Pi project and private state inside its project; deploy the clean candidate commit using tracked-file rsync and the existing service.
- [x] Verify Pi source checksums, version marker, service/SDL/API, tests, page switching/restoration, real configured data paths and device health. Capture safe Pi-rendered specimens; do not call offscreen images panel photographs.
- [x] Review known limitations for release severity and update both README languages, CHANGELOG and `docs/v0.1.2.md`.
- Final external gate, evaluated after this plan's source checkpoint: commit final version/docs, deploy that exact HEAD, verify marker/checksums/state/service again, then create and push `v0.1.2` without moving existing tags. The immutable tag and final JSON attached to the GitHub Release record the outcome without changing the verified source commit afterward.

## Review Focus

- Invalid JSON shapes, layout/slot IDs and source field types must fail before persistence, in both transports.
- No public output may include private calendar URLs, credentials, location coordinates or actual device identifiers.
- Five-page checks must restore the original private source/app configuration even on failure.
- Retained iCal recurrence/OWM/concurrent-setting limitations are not silently claimed fixed.
- Final version/tag/GitHub/Pi provenance must agree; local fixtures alone cannot pass the hardware gate.
